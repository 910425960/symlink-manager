# 软链接管理器 (Symlink Manager)

Windows 软链接管理桌面程序。**纯 Python 标准库（tkinter）实现，运行时零第三方依赖**，可用 PyInstaller 打包为小体积单文件 EXE。

---

## 术语：源路径 vs 目标路径

程序严格区分两者，避免混淆：

| 概念 | 含义 | 要求 |
|---|---|---|
| **源路径 (source)** | 真实数据所在的文件或文件夹 | 必须**已存在** |
| **目标路径 (target)** | 软链接本身被创建的位置 | 必须**尚不存在**（否则冲突） |

即：在「目标路径」处创建一个链接，指向「源路径」的真实数据。访问目标路径 = 访问源数据。

---

## 功能

- **增**：为文件或文件夹创建软链接并登记记录（软件名称 / 源路径 / 目标路径）。
- **删**：删除记录时提供三选一确认对话框——
  - 「仅移除记录」：只从管理列表删除，磁盘上的软链接**保持不变**；
  - 「同时删除软链接」：移除记录，并删除目标位置的链接本身（**绝不删除源数据**）；
  - 「取消」。
- **改**：编辑记录，包括修改软件名称、修改源/目标路径映射。路径映射变更时自动"删旧链接 + 新位置重建"，失败可**回滚**恢复旧链接。
- **查**：主界面表格展示，**列顺序固定**：`序号 | 软件名称 | 源文件夹路径 | 目标文件夹路径`，其后为详细信息列 `状态 | 类型 | 源类型 | 创建时间`（工具栏「详细列」开关或 `Ctrl+D` 可显隐）；点任意表头排序（再点反向）；顶部搜索框按名称/路径实时过滤；双击行编辑；右键可打开目标所在目录 / 复制路径 / 校验链接。
- **详情面板**：表格下方常驻显示选中记录的完整信息（状态、链接类型、源类型、创建时间、完整源/目标路径），无需弹窗。
- **持久化**：记录存于 `%APPDATA%\SymlinkManager\records.json`（UTF-8，人类可读）。
- **链接状态**：以「符号 + 文字 + 颜色」三重标注（`● 正常` / `▲ 损坏` / `○ 缺失`），不以颜色为唯一区分手段。

## 界面与交互（UI/UX）

- **布局：紧凑详细型** — 小间距刻度（3/5/8/10px）、24px 表格行高、9px 基准字号，单屏容纳更多记录；同时以更小的空间开销提供更多字段（状态/类型/源类型/创建时间列 + 底部详情面板）。
- **统一视觉系统**：中性画布 + 单一强调色（主操作蓝 `#2563eb`），语义色（成功绿 / 警告橙 / 危险红）仅用于状态；配色/字体/间距以 token 化集中管理（`COLORS` / `SPACE` / `FONT`），基于 ttk `clam` 主题定制。
- **控件层级与焦点**：主操作（新建）为强调按钮，破坏性操作（删除）为红色按钮，其余为中性按钮；焦点环统一；表格斑马纹、表头弱化、行高稳定，各状态不改变控件尺寸。
- **清晰说明与悬停提示**：工具栏每个按钮、输入框、清除键均有 Tooltip 文字说明与快捷键标注；路径字段用等宽字体展示。
- **加载状态**：磁盘 I/O（创建/重建/删除链接）在后台线程执行，超过 120ms 显示进度遮罩，避免界面冻结与闪烁。
- **失败反馈**：所有错误用带语义色标条的模态消息框呈现，说明原因与下一步（路径不存在、目标冲突、名称重复、权限不足、操作失败）。
- **成功反馈**：操作成功用非阻塞 Toast + 状态栏文字双重提示；取消操作在状态栏提示"已取消，未做任何修改"。
- **快捷键**：`Ctrl+N` 新建、`Ctrl+E`/双击 编辑、`Delete` 删除、`Ctrl+F` 聚焦搜索、`Ctrl+D` 切换详细列、`F5` 刷新、`Esc` 取消对话框、`Enter` 触发默认按钮。
- **空状态**：无记录 / 搜索无结果时显示引导文案。

## 保存决策流程（软件名称冲突处理）

保存时按**软件名称**判定是否已存在（名称是软件身份）：

- **不存在** → 弹「确认创建」对话框 → 用户确认后创建并登记，反馈结果。
  - 若目标位置已被**真实文件/文件夹**占用 → 直接报错要求更换目标（防误删）；
  - 若目标位置已是**其他软链接** → 弹「覆盖并创建」确认。
- **已存在** → 弹三选一对话框：
  - **覆盖**：直接用本次内容替换原有软件（更新同一条记录，保留 id）；
  - **重命名另存**：输入新名称，保存为一条独立软件记录；
  - **先删除再覆盖**：移除原有记录及其软链接后，写入本次内容（生成新记录，**二次确认**）。
- **取消**：任一对话框取消都安全退出，不修改任何已有数据。

> 所有询问均为模态对话框；删除类操作（先删除再覆盖、同时删除软链接）均需二次确认。四分支的核心逻辑抽为模块级纯函数 `op_create_new` / `op_overwrite` / `op_save_as` / `op_delete_then_create`，可被 `--selftest` 无 GUI 覆盖测试。

## 权限与容错

- 目录链接**优先**创建符号链接 (symlink)；遇权限不足 (`ERROR_PRIVILEGE_NOT_HELD 1314`) **自动降级为 Junction**（目录联接，**无需管理员**），并在状态栏提示。
- 文件链接需要管理员权限或开启「开发者模式」；无权限时给出明确中文提示。
- 删除链接前校验目标确为软链接/Junction，**拒绝删除普通文件/文件夹**，从根源杜绝误删源数据。
- 覆盖场景的清晰提示：路径不存在、目标已存在冲突、软件名称重复（不区分大小写/首尾空格）、权限不足、操作失败。

## 运行（源码）

```bash
python symlink_manager.py
```

自检与冒烟（不进入交互，用于验证核心逻辑与界面构建）：

```bash
python symlink_manager.py --selftest            # 核心链接逻辑 + 保存四分支纯逻辑自检
python symlink_manager.py --smoketest [结果文件] # 主窗口 + 全部对话框构建自检 + 行为级断言
```

`--selftest` 覆盖：记录 CRUD/持久化、名称查重、目录/文件链接创建与安全删除、冲突检测、拒删普通目录、目标状态分类，以及保存决策四分支（新建 / 覆盖 / 重命名另存 / 先删除再覆盖 / 取消不改数据）。共 12 项。

`--smoketest` 分两层，任一失败即退出码非 0：

1. **构建级** —— 种入 3 条样例记录（保证表格渲染路径真正执行，而非空库跑 0 次循环），构建完整主窗口与全部对话框/组件（Message / Confirm / Prompt / Conflict / Delete / Edit / Toast）。
2. **行为级** —— 对紧凑详细型的三个新功能断言控件的**可观察状态**，而不是内部标志位：
   - `behavior_sort`：连点「创建时间」表头两次 → 降序；换点「软件名称」→ 回到升序。
   - `behavior_detail_toggle`：详细列开关 → `displaycolumns` 在 8 列与固定四列 `# / 软件名称 / 源文件夹路径 / 目标文件夹路径` 间切换。
   - `behavior_detail_panel`：选中某行 → 底部详情面板文本包含该记录的名称与源/目标路径。

无 seed 数据时行为级测试标记为 `skipped` 而非失败。打包后的 EXE 跑 `--smoketest` 可确定性验证界面栈与新功能行为均完好（windowed EXE 无 stdout，结果写入指定文件）。

> 需 Python 3.8+（tkinter 为官方安装包默认组件）。

## 打包为 EXE

### 方式一：一键脚本（Windows）

```bat
build.bat
```

脚本会自动：创建 `.venv-build` 虚拟环境 → 安装 PyInstaller → 按 `SymlinkManager.spec` 打包。
也可指定解释器：`build.bat "E:\Tools\env\miniconda3\python.exe"`。

### 方式二：手动

```bash
pip install -r requirements-build.txt
pyinstaller SymlinkManager.spec --noconfirm --distpath dist --workpath build
```

产物：`dist\SymlinkManager.exe`（单文件，双击即用，无控制台窗口）。

### 体积优化要点（spec 已内置）

- **纯标准库**，无 numpy/PIL/PyQt 等重型运行时依赖；
- `excludes` 排除 unittest/doctest/pdb/pydoc/xmlrpc/multiprocessing/sqlite3 等无关模块；
- 无图标、无外部资源文件（`datas=[]`），不启用 UPX（避免杀软误报）；
- **自动收集 tkinter/ctypes 原生 DLL 依赖链**：Anaconda/Miniconda 的 Tk9 运行时把 `tcl90.dll`、`tcl9tk90.dll`、`libtommath.dll`、`zlib1.dll`、`ffi*.dll` 放在非标准的 `Library/bin`，PyInstaller 内置 hook 收集不全，会导致打包后 `DLL load failed while importing _tkinter/_ctypes`。spec 从 `_tkinter.pyd`/`_ctypes.pyd` 出发递归解析并补齐这些 DLL（对官方 python.org 构建无副作用，自动跳过缺失项）。

> 实测：Miniconda Python 3.14 + Tk 9.0 打包产物约 **12 MB**；官方 python.org（Tk 静态布局）通常 **9–11 MB**。相较 PyQt6 方案（60–90 MB）体积约为其 1/6–1/9。
